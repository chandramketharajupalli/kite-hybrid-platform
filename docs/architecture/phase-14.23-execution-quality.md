# Synthetic execution quality

phase1423.quality is an additive offline measurement layer. accepted_fills uses the existing Phase 14.21 validate function to reproduce and verify immutable Phase 14.20 outcomes through the existing scheduler and portfolio engine. It extracts FILLED and CLOSED portfolio events, preserving their event_id as distinct buy/sell fill IDs. It joins accepted order quantities, checks accepted prices/timestamps and reconciles signed cash deltas with notional and existing fees. No execution or accounting implementation changes.

The strict reference record binds schema, measurement policy, evidence ID, run, NSE session date, symbol, strategy, fill ID, side, reference type/price, observation/availability/cutoff timestamps, accepted fill price/time/quantity, synthetic provenance and canonical SHA-256. UTC transport timestamps retain Asia/Kolkata session checks. Prices use the existing bounded Decimal contract. Unknown versions, post-trade benchmark types, malformed/nonfinite prices or unverified sources are rejected.

assess is the public in-memory boundary: it obtains accepted fills from validated outcomes, then attributes references. attribute and measure are lower-level calculation helpers and are not substitutes for accepted-source validation. Duplicate reference IDs or multiple references to one fill reject all conflicting entries; input order cannot select a convenient benchmark. Rejected records retain their input hash and reason. Missing or rejected references preserve the accepted fill with NOT_COMPUTABLE measurement.

Reports contain reference evidence, accepted fill coverage, six-strategy and 1,115-symbol attribution, portfolio totals, rejection reasons and measurement policy. signed_total/absolute_total are null unless every accepted fill in that group is measured. measured_subset values describe only observed coverage and remain null when nothing is measured. Symbols without fills are explicitly NOT_COMPUTABLE, not fictional zero-slippage executions. Signed/absolute slippage, measured-fill counts, fees and cash reconcile across both attribution dimensions.

The file API uses bounded, duplicate-key-rejecting JSON reads and caller-supplied raw source/reference hashes. It publishes execution-quality.json followed by completion.json exclusively in external storage. Existing conflicting content fails closed; identical replay is idempotent. Publication binds source, references, measurement policy, software and output hashes. One worker; limits are 64 MiB source/output, 16 MiB references, 50,000 fills/references and inherited source-validation budgets. No network, broker transport or live market-data ingestion exists.

Complete-authority rollback cannot be independently detected without separately retained trusted hashes. Measured synthetic benchmark movement does not establish executable liquidity, real slippage, genuine qualification or successful completion of an underlying halted session.
