# Phase1444DRollbackResistance.v1

LEDGER_ROLLBACK_RESISTANCE_UNVERIFIED. Phase14.44C's SQLite uniqueness, transactions and chain detect ordinary replay and inconsistent local edits. A complete earlier database or reconstructed chain can remain internally consistent. File replacement, snapshot/backup restore, truncation and coherent chain replacement require a latest checkpoint independent of that replaceable store. Host or key compromise can defeat local claims; this phase provides no production replay guarantee.

Propose a separately enrolled, authenticated checkpoint authority with independent custody and monotonic generation. Checkpoint binds ledger identity, exact committed sequence/head, source baseline/policy, decision/action digest, revocation generation, trusted issuance/expiry, authority/key identity and prior checkpoint. Its current latest generation must be independently provable, not merely a valid old signed object. Protected storage, freshness, compare-and-swap concurrency and recovery guarantees remain unverified. A second file under the same operator control is not an independent anchor.

Future protocol: inspect without consuming; acquire authenticated one-use reservation for expected latest generation; persist local decision/outbox intent with unique ID/nonce; finalize checkpoint with exact committed head; dispatch only after durable independent acknowledgement. Concurrent reservation losers deny. Before local commit, release/expire a reservation under separately reviewed authority. After local commit but before checkpoint acknowledgement, fail closed and reconcile exact reservation/intent; never roll back consumption or reuse permission. After acknowledgement but before dispatch, idempotent delivery needs an approved executor. This is a proposed distributed protocol, not implemented atomicity or exactly-once execution.

On recovery require intact database, chain and externally authenticated latest head plus revocation epoch. Exact mismatch, stale checkpoint, missing authority, corruption or snapshot regression blocks; preserve originals, no silent reset/auto-repair/backup rollback. Retain evidence of crash boundaries and operator actions. Compromised owner/checkpoint keys revoke independently; rotation must preserve ledger lineage and old revocations, with separate authority approval. Full host compromise and independent-authority collusion remain explicit threats.

Synthetic policy tests compare supplied fixture state and checkpoint, and demonstrate a locked in-memory compare-and-swap race. They do not implement durable external checkpoints, detect real VM restore, or certify distributed concurrent replay prevention. C's prior physical database/concurrency/crash receipts remain historical. Its database-writing regressions are excluded here because their frozen path targets already sealed C custody; no tests or frozen modules are modified to hide this limitation.
