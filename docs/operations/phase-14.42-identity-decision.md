# Phase1442HistoricalIdentityDecision.v1

Status PENDING_OWNER_DECISION. Stable security identity requires independent evidence; exchange/symbol is a logical mapping key, while tokens are refreshable attributes. A current master cannot prove historical continuity.

Require contiguous half-open effective periods within declared scope, no conflicting overlap/gap, mapping generations and source hashes, observation/availability timestamps and explicit transition reasons/evidence. Token replacement alone does not imply a new security; matching token or symbol alone does not establish the same security. Reject unrelated-security conflation and ambiguous token reuse. Reuse across disjoint dates still requires independently justified security-history evidence; the current candidate rejects cross-security reuse conservatively.

Symbol changes need exchange records. Merger/demerger/security replacement may require separate logical identities rather than continuity. Delisting/relisting cannot silently reuse the old identity or qualification. Suspensions need evidence, not inference from absent candles. Retroactively discovered mappings may support labeled retrospective research only, never pretend to be point-in-time observations. Observation time and effective time are distinct.

Candidate timeline remains separate from legacy Series; no automatic token substitution or unsupported single-token conversion. Future owner review must decide authoritative identity sources, registry completeness scope, supported transition classes, effective/availability conventions, ambiguity handling and test corpus. Null or ambiguous evidence blocks implementation.
