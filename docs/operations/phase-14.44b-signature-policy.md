# Phase1444BSignaturePolicy.v1 — proposed

Ed25519 is the candidate, not an approved installed signing mechanism. Local Python 3.12 environment inspection found no cryptography, nacl or Crypto library, and pyproject.toml declares no cryptographic dependency. No dependency was installed. Standard-library HMAC is used solely to exercise disposable synthetic envelope binding; it does not satisfy Ed25519, public-key verification or independent owner authentication. No custom primitive is implemented.

Selection approval requires maintained-library provenance/version pinning and security review, approved Windows-provider compatibility, offline verification, deterministic signature vectors, malformed-signature rejection, fixed algorithm/no downgrade, exact public-key representation, canonical payload tests, cross-process interoperability and enforced custody. Actual Windows CNG/KSP/hardware Ed25519 support and non-exportability are UNVERIFIED: no provider enrollment or real-key operation was attempted. Software serialization or an ACL alone cannot prove non-exportability. OS-provider feasibility must be demonstrated against the selected provider, not inferred from OS branding.

Canonical JSON is UTF-8 encoding of sorted-key compact JSON using ensure_ascii=True and allow_nan=False, separators comma/colon, no newline. Envelopes contain only strict declared scalar string fields. Reject duplicate keys, extra/missing fields, unknown versions, alternate escaping, whitespace variations and noncanonical timestamps; parsing must compare exact raw bytes against canonical reserialization. Timestamp format is YYYY-MM-DDTHH:MM:SS.ffffffZ, six fractional digits, UTC. No normalization of an already signed input is permitted.

The canonical payload is the complete strict envelope excluding canonical_payload_fingerprint and signature_bytes. SHA256 of these exact bytes becomes canonical_payload_fingerprint. Signature input is ASCII(domain) followed by one NUL byte followed by canonical payload bytes. Domain and signature_algorithm also appear inside the payload. Real domain: KITE_GOVERNANCE_DECISION:Phase1444B:v1; proposed algorithm Ed25519; signature_bytes lowercase hex of exactly 64 signature bytes. Synthetic domain: KITE_SYNTHETIC_ONLY:Phase1444B:v1; algorithm HMAC_SHA256_SYNTHETIC_ONLY; lowercase hex of exactly 32 MAC bytes. The preparation parser accommodates both encodings, while the only available verifier requires the synthetic domain/algorithm and validates MAC length by comparison. A future Ed25519 verifier must enforce the real algorithm's exact key/signature lengths before verification.

Required payload bindings: version/domain/source/algorithm, decision type, owner reference, authority role, root and signing-key fingerprints, Git SHA, both amendment hashes, certificate SHA256, scope, approval/expiry, unique decision ID, 256-bit nonce, revocation reference, trusted-time reference, governance fingerprint and explicit rollback separation. No signature or fingerprint covers itself. Reject disagreement with externally established expected bindings before consuming any replay identity. A successful signature cannot substitute for independently verified identity, authority, revocation or time.

Real signature tests (valid, tampered, wrong public key and cross-process) are NOT_RUN_DEPENDENCY_UNAVAILABLE. Corresponding HMAC fixture tests are explicitly narrower evidence. Real owner signature and key enrollment remain absent.
