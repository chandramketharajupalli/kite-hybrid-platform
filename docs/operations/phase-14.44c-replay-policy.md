# Phase1444CDurableReplayLedger.v1

TEST_ONLY. New databases require an exclusive create and TEST_ONLY ledger identity. Reopen requires expected identity, exact schema, integrity check and audit-chain consistency. mode=rw prohibits silently creating missing storage. Reject symlink/junction paths and destinations outside the new custody. Path checks assume exclusive operator custody; hostile concurrent filesystem alias changes and whole-store rollback are not solved by these checks.

Inspection verifies records without consumption. Consuming validates a strict synthetic decision inside BEGIN IMMEDIATE: current persisted revocations, baseline/hashes, enrolled-fixture/time evidence, approval/expiry and monotonic prior timestamp. Unique decision-ID and nonce constraints reject either replay. Persist decision and audit event in one transaction; synchronous FULL and rollback journal are explicitly used. Time is sampled again immediately before commit; expiry/rollback during the transaction aborts. The stored consumption timestamp is the validation instant, not a claim of independently authenticated physical commit time.

Crash before commit rolls back, so the same fixture may be retried after integrity checks. Crash after commit leaves a consumed decision; repeat consumption denies even if the caller did not see the response. No action is dispatched here. A future executor must atomically persist a unique authorized action/outbox intent with consumption and implement audited idempotent delivery; this module alone cannot prove exactly-once external actions. Read-only signature verification is never execution permission.

Revocation uses the same exclusive transaction mechanism and append-only audit history. If revocation commits first, consumption denies. If consumption commits first, later revocation does not erase the historical consumption; it blocks later decisions. Tests cover both serial orders including concurrent writers. An external revocation source or action after commit needs a separately approved freshness/recheck policy; this fixture does not solve that external race.

Audit digest = SHA256(previous_digest ASCII + NUL + canonical event JSON). Genesis binds ledger identity; sequence gaps, altered hashes, table/event inconsistencies and wrong schema/identity deny. ID/nonce uniqueness persists across processes/restarts. Hash chaining is tamper-evident against uncoordinated edits, not a signature: an administrator can rebuild a whole chain/store. Independent anchor identity/checkpoint and rollback-resistant recovery are REQUIRED and UNVERIFIED. No silent ledger reset, backup restoration or authority restoration is authorized.

Backup/recovery must retain ledger ID, last independently anchored checkpoint, revocation generation and full event history; reconcile checkpoints before reopening. Missing/corrupt storage, lock timeout or integrity failure denies. Retain original corrupt evidence; do not auto-repair/delete/recreate. Physical power loss, network filesystems, malicious administrator recovery and production action dispatch were not certified. Synthetic crash tests terminate child processes, not hardware power.
