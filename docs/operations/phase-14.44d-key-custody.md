# Windows custody and enrollment prerequisites

HARDWARE_KEY_CUSTODY_UNVERIFIED. Existing provider enumeration is observational, not non-exportability certification. CNG, TPM/Platform, SmartCard and a possible external HSM need exact provider/device/firmware identity, advertised Ed25519 support, independently verified signing interoperability, enforced key-export policy, role ACLs, audit records, backup/recovery and rotation/revocation evidence. Algorithm availability in a software library does not imply availability in a TPM/HSM. File ACLs do not establish hardware non-exportability. No real key is generated/opened/enrolled and no HSM is assumed present.

Owner enrollment NOT_PERFORMED. Prerequisites: independently verified identity and governance role; separate enrollment authority; approved provider/provenance; public-key fingerprint; attested custody and proof of possession under an approved protocol; enrolled root; trusted time/revocation; independently protected replay checkpoints; exact allowed decision types; timestamp/expiry and independent approval receipt. Unknown identities, keys, times and authority evidence remain null. A synthetic key or TEST_ONLY flag cannot become real trust.

Lost/compromised key: stop acceptance, preserve evidence, independently revoke key and owner role as appropriate, reconcile all pending decisions and checkpoint reservations. No silent restoration. Rotation requires separate authenticated approval and signed old/new lineage where policy permits; lost-key recovery uses independent authority, not the compromised key alone. Backup scope, encryption/access custody and disaster recovery must be reviewed without exporting a key claimed non-exportable. Enrollment, rotation, rollback execution and amendment adoption remain separate NOT_AUTHORIZED operations.
