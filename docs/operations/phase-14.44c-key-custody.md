# Phase 14.44C Windows custody assessment

Read-only NCryptEnumStorageProviders/NCryptEnumAlgorithms discovery opened provider handles only and freed them. No key enumeration, key opening, private-key access or generation occurred. Microsoft Software Key Storage Provider advertised RSA/DH/DSA/ECDH/ECDSA/AES and other algorithms including ML-DSA/ML-KEM, but no Ed25519 name. Passport advertised RSA. Smart Card advertised RSA and ECDH/ECDSA curve variants. Platform Crypto Provider opened but enumerated zero algorithms. Pluton open returned -2147467263. Exact results are in provider-discovery.json.

These observations do not prove all possible Windows implementations lack Ed25519 or that a TPM is absent. Hardware availability, TPM-backed Ed25519, operator signing permission, user presence, backup, signing auditability and provider-enforced non-exportability remain UNVERIFIED. No provider was approved or selected. Directory ACLs protect evidence access; they do not provide hardware-enforced key non-exportability.

Before real generation, separately approve the provider/version, algorithm interoperability, restricted signing roles and export-denial tests using an explicitly authorized test key. Real owner key generation remains separately gated. Private keys must stay outside Git/manifests/logs. Provider-supported protected backup, recovery authority and retention require independent approval before use. No plaintext export or silent software fallback.

Owner-role, signing-key, decision and root revocation must persist and bind current authenticated authority. Rotation requires separately authenticated old/new key/root references, activation/revocation times, proof of possession and independent enrollment evidence. Key compromise/loss suspends authority; recover through a new independently verified ceremony, not automatic trust restoration. The synthetic ledger records revocations only and never rotates or enrolls real keys. Historical evidence must remain immutable.
